# Solaris build56 실제 구현·검증 기록

2026-10-11. GitHub build54 main `4c50dbe33721b5d10db714bd79da74267a8863b4`에서 이어진 build55 로컬 체크포인트 `3f3dcc7`을 보강했습니다. 개발 브랜치는 `codex/solaris-build56-recovery`입니다. 기존 구현을 재사용한 중간 저장본이며 전체 요구사항이 완료된 정식 출시판은 아닙니다.

## 이번 코드 변경

- **파일 완료·취소:** 디스크 검증/저장을 기다려 취소하고, 이미 검증된 저장이 끝났다면 늦은 취소/완료 신호 실패가 파일을 실패 상태로 바꾸지 않습니다. 양쪽 완료 알림은 한 번씩 발생합니다. 무결성 오류는 자동 수락·재시도 반복을 중단합니다.
- **파일 복구:** 사용자 수동 정지, 모바일 백그라운드, 네트워크 단절을 구별합니다. 상대방 재시도가 수신자의 수동 정지를 풀지 못합니다. 다시 선택한 송신 파일의 크기와 원본 SHA-256을 확인합니다. 누락된 요청은 재안내하되 수신 동의를 생략하지 않습니다. 한 scope의 실패가 다른 전송까지 정지시키지 않습니다.
- **브라우저 디스크:** staged writer를 닫아 실제 저장한 뒤 디스크 해시를 읽습니다. 승인된 FileSystemHandle을 IndexedDB에 보관하고 페이지 재로딩 후 권한을 확인해 이어받습니다. 네이티브 수신은 청크를 디스크에 저장하며 전체 파일을 메모리에 올리지 않습니다.
- **생명주기:** DOM 및 네이티브 알림을 중복 없이 순서대로 처리합니다. 모바일 백그라운드에서 파일 체크포인트를 남기고 복귀 시 권한·세션을 동기화합니다. Windows 최소화는 명시적인 파일 정지 사유에서 제외했습니다.
- **Android 방송:** `BroadcastSignals.java`가 WebView 밖에서 신호 수신, 방송 lease, 보호 세션 갱신 및 권한 확인을 담당합니다. JS 이중 offer/heartbeat를 방지하고 오래된 캡처 콜백 및 시청자별 오류를 구별합니다. 실제 종료 시 foreground service를 정리합니다. 파일 완료 알림을 Android 알림으로 변경했습니다.
- **방송 상태·권한:** 준비와 실제 캡처를 `ready`로 구별합니다. 준비만 한 방송은 다른 사용자에게 시청 가능으로 노출하지 않습니다. 서버에서 나간 친구는 해당 채널 영상 연결을 유지할 수 없습니다. WebView 재로딩 시 실제 native 방송 상태와 중지 버튼을 복구합니다.
- **iOS 코드:** WK 프로세스 종료 시 페이지 재로딩, 생명주기 알림, 파일 내보내기 IO 큐, ReplayKit 실행 상태 및 오래된 연결 방어를 추가했습니다. 앱·확장의 CPU 누적 시간/상주 메모리 진단과 macOS 시험을 추가했습니다. Swift 변경은 아직 컴파일되지 않았습니다.
- **계정·진단:** 보호 저장소 쓰기를 직렬화하고 늦은 refresh가 복구한 다른 계정을 덮어쓰지 않도록 합니다. 이메일 연결/갱신 UID를 검증하며 계정 전환 시 이전 방송/파일 연결을 닫습니다. 손상된 설정은 계정 저장소 삭제 없이 복구합니다. 계정별 로그는 200개/64KiB 이내로 보관하며 자격 증명 문자열·토큰·SDP·ICE를 제거합니다. 방송 닉네임/사진도 갱신합니다.

마이크·음성통화·음성 메시지는 추가하지 않았습니다. 기존 시스템/앱 재생 오디오 경로는 유지했습니다. 원본 파일을 재인코딩하거나 대용량 파일을 Supabase Storage에 업로드하지 않습니다.

## 남은 검증 및 기술 경계

1. 신규 DB는 `backend/001_solaris.sql`, 이미 build55 SQL을 적용한 DB는 `backend/002_build56_broadcast_ready.sql`을 사용합니다. upgrade는 UID/프로필/친구/서버 삭제 없이 ready/RPC를 갱신합니다. 운영 DB에는 적용하지 않았습니다. 익명 Auth/이메일 OTP와 같은 UID 복구도 운영 검증이 남았습니다.
2. Android 백그라운드 방송·새 시청자·토큰 만료·재시작은 실제 기기 미검증입니다. 화면공유 service가 파일까지 계속 실행시킨다는 뜻은 아닙니다. 모바일 파일은 OS 정지 시 멈추고 복귀 후 이어받습니다.
3. 브라우저 writer를 닫기 전 강제 종료하면 마지막 staged 청크가 사라질 수 있습니다. 복귀 시 실제 offset/hash를 확인합니다. 원본 권한을 복구하지 못하면 파일을 다시 선택해야 합니다. 디스크 부족/권한 회수도 실제 플랫폼 시험이 남았습니다.
4. Windows 최소화 중 장시간 WebView 타이머/lease, iOS App Group 및 WK/ReplayKit 프로세스 재시작을 확인해야 합니다.
5. Windows ↔ Android, Windows ↔ iPadOS, Android ↔ iOS, iOS ↔ iPadOS, 양방향 동시 공유, 시작 순서/늦은 참여/5명/다중 방송/전체화면, 네트워크 전환 및 실제 1GiB 전송·화면공유+파일 동시 사용은 **모두 실제 기기 미검증**입니다. 1440p60/1080p60 지연·발열·성능도 미검증입니다.
6. Windows 설치 EXE와 iOS IPA는 아직 생성되지 않았습니다. CI 스크립트 존재를 성공으로 보고하지 않습니다. 정식 서명·자동 업데이트/rollback·설치파일 서명/해시 확인은 남아 있습니다. 현재 업데이트는 공식 링크를 사용자 선택으로 여는 단계입니다.
7. APK는 debug 서명입니다. 소유자의 안정된 출시 서명키를 정식 배포 전에 고정해야 합니다. 다른 서명 APK는 덮어설치되지 않을 수 있습니다. 계정 복구 연결 없이 앱을 삭제하지 마세요.
8. 모든 NAT에서 STUN 직접 연결을 보장하지 않습니다. TURN 중계 및 오프라인 저장소 비용은 무료 P2P와 별개입니다. 서버 관리 권한은 앱 릴리스/서명/DB 최고 권한과 분리되어 있습니다.
