# 0.3.2 — 한 번 방송으로 통합 확인

앱 첫 화면은 **0.3.2 (build 5)**, Windows 페이지 제목은 **0.3.2**이어야 합니다.
이전 버전의 P2P 연결 테스트는 사용하지 않습니다.
기존 Supabase 프로젝트와 solaris_signals 테이블을 그대로 사용합니다. SQL을 다시 실행할 필요는 없습니다.

1. 진행 중인 아이패드 방송을 중단하고, Windows의 옛 Solaris 탭을 닫습니다.
2. 아이패드 **1 · 화면 방송 설정**에 URL, Publishable key, 방 ID를 넣고 저장합니다.
   방 ID 예: `solaris-screen-31`. 키 입력은 비밀번호처럼 가려집니다.
3. Windows에서 **Solaris-Windows-0.3.2.html**을 Chrome으로 열고 같은 세 값을 입력합니다.
   소스 폴더의 `ios/App/Resources/solaris-p2p.html`도 동일한 파일입니다.
4. Windows **설정 저장 + 수신 시작**을 한 번 누릅니다.
5. 아이패드 **2 · Windows 수신 시작 후 방송 시작**의 동그란 버튼을 눌러
   **Solaris 화면 시험 → 방송 시작**을 선택합니다.
6. 아이패드 홈 화면을 움직이거나 설정 앱을 스크롤합니다.
   Windows에서 영상이 움직이고 **⑤ 영상 수신 프레임 증가, ⑥ 화면 재생**이 확인되면 성공입니다.

## 자동 확인 항목

신호 서버 → 방송 확장 응답 → WebRTC 연결 → 영상 트랙 → 디코딩 프레임 → 화면 재생.
메시지 연결 또는 녹화 표시만으로 화면 전송 성공이라고 판단하지 않습니다.
아이패드 진단의 입력 프레임은 인코더에 넣은 수이며, 실제 도착한 수는 Windows에서 확인합니다.

## 문제가 남으면

15초 이상 영상이 없으면 **Windows ‘진단 한 번에 복사’**를 누르세요.
아이패드 앱의 **3 · 자동 진단 → 진단 한 번에 복사**도 함께 보내면
송신과 수신 중 어느 쪽이 막혔는지 확인할 수 있습니다. 키를 다시 보내지는 마세요.

0.3.2에서는 아이패드 진단에 `processMode=RPBroadcastProcessModeSampleBuffer`와
확장 `version=0.3.2 build=5`가 포함됩니다. 다른 값이면 다른 설치본입니다.
`commonProfileGroups`는 프로파일의 공통 그룹 표시이며 확장의 실제 접근 성공을 보장하지 않습니다.
방송 시작 후에도 진단이 없으면 설치본의 처리 모드와 오류 코드가 함께 복사되므로
방 이름 변경이나 같은 설치를 반복할 필요가 없습니다.

다시 시도할 때는 아이패드 방송 중단 → Windows 수신 중지 → Windows 수신 시작 → 아이패드 방송 시작입니다.
방 이름을 매번 바꿀 필요는 없습니다. Windows가 새 세션 번호를 만듭니다.
설정 변경은 실행 중인 방송에 적용되지 않으므로 방송을 다시 시작해야 합니다.

이 버전은 영상만 전송합니다. 일부 네트워크는 TURN이 필요하지만 현재 포함되어 있지 않습니다.
화면 송신 성공은 실기기에서 확인해야 하며 이 문서가 성공을 보장하지 않습니다.
