# build46 진단 및 검증

build45 세션 `5075b5c1-3425-45a9-9c03-576b60a3e476`에서 목표 비트레이트가 12→7→4Mbps로 낮아졌다. 두 번째 재시작은 C# `Math.Clamp(4, 8, 6)`에서 상한이 하한보다 작아 예외가 발생했다. build46은 이 역전 조건을 없애고 Windows 실행 파일의 자체 검사에 4Mbps/6Mbps 인코더 인수 검증을 추가했다.

이 진단에서 송신 채널 큐는 약 2MiB에 닿았고, 프레임 드롭은 456건이었다. `availableOutgoingMbps` 최종값은 0.088이었으나 WebRTC 후보 쌍의 추정치이므로 실측 전송 대역폭으로 단정하지 않는다. 초기 FFmpeg 출력 FPS가 60 요청보다 높게 표시된 구간도 있었다. iPad의 동일 세션 수신 진단 없이 안정적인 1080p60 달성을 판정할 수 없다.

검증 순서: GitHub Actions의 Windows `--self-test`와 iOS 빌드를 통과한 뒤, Windows와 iPad에 동일한 build46을 설치한다. 1분 이상 움직임이 많은 화면을 공유하고 같은 세션 ID의 양쪽 진단에서 송신 드롭·채널 큐·목표 비트레이트와 iPad 최근 완료 FPS·수신 Mbps를 함께 확인한다.

여러 명 동시 시청과 플랫폼별 1080p60 보장은 아직 구현되거나 입증되지 않았다.
