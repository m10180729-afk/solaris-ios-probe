# Solaris build58 구현 및 검증

이 버전은 실제 코드 수정과 자동 검증을 포함한 테스트 체크포인트입니다. 사용자가 보고한 13fps와 Android 프로세스 충돌이 실기기에서 해결되었다고 판정하지 않습니다.

## 빌드54 복원

GitHub main의 `4c50dbe33721b5d10db714bd79da74267a8863b4`를 직접 조회했습니다. 새 Windows 캡처의 1440p / Lanczos 변경을 제거하고 **NativeH264Capture.cs 전체를 빌드54 원본 그대로** 복원했습니다. 통합 방송은 원래의 1080p60 / fast_bilinear / 12–18Mbps / H264 baseline level 4.2 설정을 사용합니다.

iOS의 새 UnifiedBroadcastSender가 자체 캡처 소스를 만들던 구조도 제거했습니다. 기존 BroadcastWebRTCSender의 ReplayKit 캡처와 프레임 처리 루프를 직접 호출하고 같은 H264 VideoToolbox 팩터리와 RTP 정책을 사용합니다. 원본의 최대 긴 변 1920, 60fps, 28–60Mbps 요청을 유지합니다. iPad의 화면 비율을 16:9로 강제하지 않습니다. 친구·채널 권한과 신호 연결에는 인증 어댑터를 사용하므로 모든 연결 코드를 이전 버전으로 되돌린 것은 아닙니다.

`scripts/check_build54_capture.py`가 원본 Windows 파일 전체와 iOS 캡처·프레임 처리 블록의 SHA-256 일치를 확인했습니다. 기준은 `docs/BUILD54_CAPTURE_REFERENCE.json`에 기록했습니다. 코드 일치 검사는 실제 FPS 측정과 구별합니다.

수신 영상과 앱 오디오가 스트림 ID 없이 도착하거나 다른 스트림 ID로 도착해도 하나의 재생 스트림에 합칩니다. 오디오가 영상의 재생 대상을 덮어쓰거나 같은 재생 스트림을 불필요하게 다시 연결하는 문제를 수정했습니다.

## 로그인, Android, 서버와 개인 대화

- 이메일·비밀번호 가입 / 로그인 / 비밀번호 재설정 / 인증된 계정 로그아웃을 추가했습니다. 비밀번호는 계정 저장 데이터에 기록하지 않습니다.
- 기존 기기 계정은 이메일 인증 후 같은 UID에 비밀번호를 연결합니다. 인증 전 비밀번호 변경과 UID가 바뀌는 이메일 연결을 거부합니다.
- Android는 1080p급 캡처와 최대 18Mbps 요청, H264 baseline 우선, 기존 하드웨어 인코더 fallback을 사용합니다. 첫 프레임 전에 방송 준비 완료를 알리지 않습니다.
- 캡처 재시작마다 별도 수명 토큰을 사용합니다. 방송 ID가 재사용되어도 이전 캡처의 종료·리사이즈·준비 콜백이 새 캡처를 종료하지 못하도록 수정했습니다.
- Android 실제 캡처 FPS와 시청자별 인코딩 FPS·코덱·병목을 수집합니다. WebView 복구, 화면 여백, 전체화면 뒤로 가기, 방송으로 돌아가는 알림을 정리했습니다.
- 친구 선택은 개인 대화 화면으로 이동합니다. 요청 수락 / 취소 / 재접속과 수락된 개인 방송 발견을 연결했습니다. 메시지 기록은 계정과 친구·채널별로 나눕니다.
- 서버 생성 / 참여는 생성된 서버의 기본 채널로 연결합니다. 채널 이동·퇴장과 화면 상태를 함께 갱신합니다. 서버 / 채널 생성·이름 변경·삭제 확인을 앱 내부 입력창으로 바꿨습니다.
- Discord와 비슷한 서버 아이콘 열, 채널·개인 메시지 목록, 친구 필터, 콘텐츠 영역, 참여자 목록, 프로필 옆 접속 표시를 구성했습니다. 모바일에서는 탐색 목록을 서랍으로 표시합니다. 변경 없는 주기 조회는 UI 입력창을 다시 만들지 않습니다.
