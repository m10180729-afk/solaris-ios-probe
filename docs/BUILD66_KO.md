# Solaris build66 — Google 전용 가입·로그인

Windows, Android, iPhone, iPad에서 `Google로 계속하기`로 가입·로그인합니다. 처음 인증하는 사용자만 고유 ID와 닉네임을 정합니다. ID는 프로필·친구 검색에 사용하며 설정에서 변경할 수 있습니다.

이메일·ID·비밀번호 로그인, 이메일 가입·인증 코드·비밀번호 복구·변경 화면을 제거했습니다. 설정에는 인증된 Google 계정과 로그아웃·회원 탈퇴가 표시됩니다. 다른 Google 계정을 쓰려면 먼저 로그아웃합니다. 가입·로그인에 SMTP 설정이나 인증 메일이 필요하지 않습니다.

기존 회원·프로필·서버·친구 데이터를 초기화하지 않습니다. 기존 이메일 가입 사용자는 같은 인증된 이메일의 Google 계정으로 로그인하면 Supabase의 자동 계정 연결에 따라 기존 UID와 데이터가 유지됩니다. 다른 이메일의 Google 계정은 별도 계정입니다. 이전 이메일 로그인 세션은 Google 인증으로 전환해야 합니다.

서버의 이메일/익명 로그인 경로를 비활성화하고, Solaris RPC와 아바타 접근은 인증된 Google identity·OAuth 인증 기록·현재 유효한 세션을 함께 확인합니다. 이전 앱의 ID 로그인 요청과 비공개 ID→이메일 조회도 차단합니다. 프런트엔드에는 공개 프로젝트 키만 포함합니다. 기존 유효한 인증으로 본인 계정의 탈퇴 정리를 마무리하는 경로는 유지하며, 다른 계정이나 일반 데이터 접근 권한은 부여하지 않습니다.

Google PKCE 복귀, 앱 재시작 시 복귀 보관함 처리, 오프라인 로그아웃을 유지합니다. 탈퇴 도중 서버 정리가 실패하면 같은 계정의 정리 재시도 화면이 앱을 다시 열어도 유지됩니다. 늦게 도착한 세션 복구나 인증 요청이 새 로그인을 덮어쓰는 경쟁 문제도 수정했습니다.

build65의 Android 화면공유 시청 전용, 화면 확대·축소, 연결 종료 처리, ID 변경, 접속 상태, 모든 서버 멤버의 초대, 은하 로고는 유지합니다. Windows build54 캡처·전송 엔진은 변경하지 않습니다.

검증은 단위 테스트, 실제 Chromium의 모의 Google PKCE 복귀·반응형 UI, PostgreSQL 호환 DB fixture, 플랫폼 빌드와 설치 파일 검사를 구분합니다. 실제 Google 계정 로그인 및 물리 기기 설치·화면공유 품질은 자동 fixture 결과만으로 완료로 간주하지 않습니다. iOS/iPadOS IPA는 설치 전 본인의 서명과 App Groups entitlement가 필요합니다.

기존 프로젝트에 006을 적용하기 전에 001·003·004·005가 적용돼 있어야 합니다. 관리 마이그레이션은 `supabase/migrations/20261014082301_google_only_auth_build66.sql`이며 `backend/006_build66_google_only.sql`과 같습니다. 새 검토 브랜치 빌드의 Windows EXE, Android APK, 재서명 후보 IPA를 사용합니다.
