# Solaris build62 구현과 검증 상태

기준: build61 `fba5247ab367baee7d3ec19007f849157e90d28f`. 작성일: 2026-10-12. 사용자의 실제 Google 로그인, Android 화면공유, 로그아웃, Windows 창 조절·화질 비교, PC·모바일 UI 요청에 대한 수정이다.

## 구현한 변경

- Windows: 전체화면 해제 시 일반 창 테두리·최대화 상태를 잃는 문제 수정. 최소화·최대화·복원·닫기 브리지와 F11/Escape, 창 상태 동기화.
- 인증: Windows 콜백의 잘못된 경로·메서드·상태·중복 코드, 끊긴 브라우저 연결과 지연 클라이언트 처리. 앱 재실행 후 유효한 PKCE 요청 복구, 로그아웃 중 늦게 도착한 인증 결과 무효화.
- Android: 공유 승인마다 구분되는 요청 코드, 취소·이전 결과 차단, 서비스·첫 프레임까지 요청 유지, 실제 중지 후 다음 시작 진행. 오래된 중지 요청이 새 방송을 멈추는 문제 차단.
- Android 패키지: 휴대폰 배포 ABI를 ARM64·ARMv7로 제한하고 실제 APK의 LOAD·GNU_RELRO·ZIP 16KB 검사와 ARM64 필수·x86 제외 검사를 CI에 추가. 현재 x86_64 WebRTC 라이브러리의 RELRO 경계 오류를 배포에서 제외하며 캡처 엔진·WebRTC 버전은 유지.
- 로그아웃: 계정 영역·내 계정 설정에서 접근. 익명 계정 경고와 취소, 공유·시청·파일 작업 정리, 보호 저장소 세션 제거, 화면 개인 정보 제거. 오프라인에서도 로컬 종료하며 서버 미확인을 정확히 표시.
- UI: 친구의 보조 동작 메뉴 정리, 모바일 공유 이름 표시, 입력창 파일 첨부, 받은 요청·공유 상태 표시, 통합 설정 탭, 데스크톱 팝업 크기 조절, 모바일 서랍 Escape·포커스 처리.
- 진단: 실제 화면공유 통계와 제한된 로그의 보기·저장, Android 실패 단계와 기기·OS·WebView 정보. 인증 정보 제거. 업데이트 확인 버튼의 공개 릴리스 조회 구현.

브라우저의 Google 공급자는 시험용 모사이며 실제 Google 계정을 사용하지 않았다. Windows 브리지 UI 시험은 주입된 브리지이고, 실제 창 자체의 검증은 별도 WinForms 시험이다. Android JVM 통과는 APK 설치·화면 공유 성공의 증거가 아니다.

## CI에서 추가로 확인한 결과

[통합 CI 38238975267](https://github.com/m10180729-afk/solaris-ios-probe/actions/runs/38238975267)는 소스 `2024c589536c782c5d608bffb1635c7c9fab6a1f`에서 5개 작업 모두 성공했다. [초안 PR #1](https://github.com/m10180729-afk/solaris-ios-probe/pull/1)은 build61 브랜치를 기준으로 작성했다.

- 브라우저: 5명 시청·동시 역방향 공유·독립 재입장과 원본 8,388,731바이트 파일 전송·수동 일시정지/재개·양쪽 디스크 SHA-256 일치까지 통과. 정규 UI·모바일 번들 UI, JavaScript 113개·DB 18개도 통과했다. 같은 기준으로 CI에서 성공했으며 로컬의 시간 초과를 숨기거나 시험 기준을 낮추지 않았다.
- Native RTP: 실제 Chrome 2개가 1920×1080 H264/SRTP를 동시에 약 60.8fps로 디코딩했다. 한 수신자의 연결 복구 때 다른 수신자가 유지됐고 최종 손실·드롭은 0이었다. Linux 실제 전송 타이머는 18.18Mbps로 통과했다. 이 수치는 시험 영상/CI 환경이며 사용자의 GPU와 인터넷 품질을 증명하지 않는다.
- Windows: 실제 Windows 호스트의 인증·창·전송 시험, 자체 포함 앱 publish, 패키지 self-test, 단일 설치 프로그램 생성이 성공했다.
- Android: 최초 CI에서 API35 전체 Java 컴파일·25개 JVM 테스트·APK 생성/서명 검증·LOAD/ZIP 16KB 정렬 검사가 성공했다. 추가 공식 RELRO 기준을 적용해 기존 ARM64 라이브러리 통과와 x86_64 라이브러리 실패를 실제 APK에서 확인했다. 현재 휴대폰 배포는 x86 계열을 제외하고 LOAD·RELRO·ZIP·휴대폰 ABI 검사를 모두 적용한다. 최종 APK는 이 검사를 통과한 후속 CI 산출물을 사용하며 해당 실행과 해시는 배포 파일의 검증 기록에 남긴다.
- iOS: Xcode 프로젝트 생성과 서명 전 재서명 후보 빌드가 성공했다. 실제 설치·ReplayKit 실행은 별도 확인 대상이다.

## 운영 설정 확인

Supabase Solaris test `lfwjkaipghctigswxoxq`의 build61 마이그레이션 적용을 확인했다. 새 SQL이나 데이터 삭제를 수행하지 않았다. Google·Manual Linking은 이미 활성화되어 있었다.

로그인 실패 당시 Site URL은 `http://localhost:3000`, Redirect URLs는 빈 목록이었다. 소유자의 명시적 승인 후 Windows `http://127.0.0.1:43854/auth/callback**`, 모바일 `solaris://auth/callback**` 두 패턴을 등록하고 저장된 2개 항목을 화면에서 확인했다.

## 별도 확인이 필요한 항목

실제 Google 계정의 인증·복귀, Galaxy Quantum2 Android14 및 최신 Android의 전체/앱 화면 공유, 실제 Windows GPU의 인코딩·시청 FPS·장시간 최소화, 인터넷 품질 비교, iOS 설치·ReplayKit, 실제 메일 도착은 아직 검증하지 않았다. Windows 1080p60·12/18Mbps 정책이 build54와 같아도 실측 품질은 별도로 확인해야 한다.

Android 전체 APK·Windows 설치 프로그램·iOS 재서명 후보 생성은 위 CI에서 확인했다. Android 최종 배포에는 휴대폰 ABI/RELRO 검사까지 통과한 후속 APK를 사용한다. CI 디버그 APK 서명 키가 이전 APK와 다를 수 있다. 기존 익명 계정의 복구를 확보하기 전 앱을 삭제하지 않는다. main 병합과 공식 릴리스는 별도 승인 대상이다.
