# build37 — Windows 네이티브 호스트 1차 통합

## 확인된 원인

고성능 PC의 build36 진단에서도 브라우저 캡처는 평균 약 47fps, 최고 약 49fps였고 인코더는 OpenH264였습니다.
인코딩 시간과 네트워크는 충분했으므로 브라우저 튜닝을 종료하고 네이티브 호스트로 전환합니다.

## 이번 빌드 범위

- Windows용 자체 포함 단일 실행 파일을 GitHub Actions에서 빌드합니다.
- Solaris 런처가 공식 Apollo winget 패키지의 설치와 서비스를 관리합니다.
- GPU·주사율과 호스트 상태를 진단합니다.
- HTML의 네이티브 버튼이 등록된 Solaris 런처를 엽니다.
- iPad에서는 공식 Moonlight로 1080p120, 하드웨어 인코딩, 시스템 소리를 우선 검증합니다.

## 의도적으로 아직 하지 않는 것

- Apollo/Sunshine 바이너리를 소스 ZIP에 재배포하지 않습니다.
- NVENC가 확인되기 전에 하드웨어 인코딩 성공으로 표시하지 않습니다.
- Moonlight GPL 코어를 아직 Solaris IPA에 복사하지 않습니다. 외부 검증 성공 후 라이선스와 빌드 구조를 함께 통합합니다.

## 성공 기준

- Apollo 로그에서 NVENC, Quick Sync 또는 AMF 확인.
- Moonlight 수신 1920×1080, 실제 100fps 이상.
- 시스템 소리 정상, 마이크 전송 없음.
- 프레임 드롭 1% 미만, 장시간 심각한 끊김 없음.
