# Solaris build67 — 화면공유 수명과 연결 복구

Windows의 한 시청자 SDP/ICE 처리 오류가 전체 방송의 캡처 오류로 전달되던 경로를 분리했습니다. 오래된 방송 중지·시청자 이탈·복구 명령은 현재 방송과 새 연결을 지우지 않습니다. 이탈한 연결의 늦은 ICE는 폐기하며 새 세대의 재입장은 허용합니다. 실제 캡처 오류는 기존 종료 경로를 유지합니다.

공통 화면공유는 일시적 연결 손실에 복구 시간을 주고 시청자 연결을 따로 정리합니다. 시청자별 신호 대기열은 각 연결 안의 순서를 유지하면서 느린 한 시청자와 관계없이 다른 시청자의 신호와 동기화를 진행합니다. 영상 통계 조회가 멈춰도 독립된 viewer heartbeat가 기존 시청 동의를 갱신합니다. 수신 복구는 진행 중인 요청과 반복 횟수를 제한합니다. 성공한 제어 요청과 영상 진행을 구분해 진단합니다.

iOS 방송 확장은 정상 RTP 연결이 살아 있는 동안 지연된 동기화만으로 방송을 끝내지 않습니다. 방송 생존 확인과 신호 동기화의 진행 중 요청을 분리하고, 공유 컨텍스트·인증 갱신은 방송 ID와 인증 세션을 다시 확인한 뒤 저장합니다. 중지하거나 교체한 방송은 늦은 인증 응답으로 다시 생성되지 않습니다.

서버 007은 기존의 허용된 시청자 동의만 자신의 heartbeat로 갱신합니다. 방송 발행자의 생존 확인, 인증된 Google OAuth 세션, 친구·서버 권한, 최대 5명, 신호 크기·속도 제한은 유지합니다. 직접 이탈·방송 중지는 늦은 heartbeat로 복원할 수 없습니다. `backend/007_build67_sharing_resilience.sql`과 `supabase/migrations/20261014132549_sharing_resilience_build67.sql`을 함께 보관합니다. 적용에는 기존 001·003·004·005·006이 필요합니다. 회원·프로필·친구·서버 초기화는 포함하지 않습니다.

Windows build54 캡처 파일, 네이티브 코어 6개와 공통 화면 정책 6개는 기존 해시 검사를 유지합니다. 네이티브 수신 화면의 위치·크기가 같으면 반복 geometry IPC를 보내지 않아 영상 위의 불필요한 작업을 줄입니다. Android는 시청 전용이며 Google 전용 가입·로그인, 파일 상한 100MiB와 이전 기능은 유지합니다.

서버 007 적용 후 계정 3개·프로필 3개가 유지됐고 공개 RPC와 비공개 delegate의 권한을 확인했습니다. 회원 초기화나 삭제를 실행하지 않았습니다. 로컬 공통 JS 208개·DB fixture 61개·Windows 어댑터 14개·전송 25개 검사는 통과했습니다. iOS Foundation 26개 회귀 그룹, 실제 브라우저 시험, 플랫폼 컴파일과 설치 파일의 버전·해시 검사는 최종 CI 및 `Solaris-build67-final-verification.json`의 항목별 결과로 확인합니다. Python 검사에서 환경 때문에 건너뛴 항목은 통과로 계산하지 않습니다.

이 변경은 재현된 종료·경쟁 경로를 수정합니다. 사용자의 실제 GPU·네트워크 끊김 원인, 물리 기기의 Google 인증·FPS·디코딩·ReplayKit 동작은 자동 fixture 결과만으로 검증 완료로 간주하지 않습니다. IPA는 설치 전에 본인의 서명과 App Groups entitlement가 필요합니다.
