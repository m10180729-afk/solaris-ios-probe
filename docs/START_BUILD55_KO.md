# Solaris build55 개발 테스트판

build54의 네이티브 전송 코드를 유지하고 공통 계정·친구·서버·파일 전송 앱을 추가했습니다. 정식 출시판이 아닙니다. 실제 기기 설치, 네트워크 전환, 1440p/60fps 성능은 기기에서 검증해야 합니다.

## 먼저 해야 하는 서버 설정

1. 기존 Supabase 프로젝트의 SQL Editor에서 `backend/001_solaris.sql`을 한 번 실행합니다. 기존 build54 테이블은 삭제하지 않습니다. 이미 실행했다면 다시 실행하지 마세요.
2. Authentication에서 익명 로그인을 활성화합니다. Storage에는 마이그레이션이 만드는 비공개 `solaris-avatars` 버킷을 사용합니다.
3. 계정 복구를 쓰려면 Auth 이메일 템플릿에 `{{ .Token }}` 인증 코드를 포함하세요. 실제 이메일 연결과 다른 기기 복구는 아직 장치 검증 전입니다.
4. 기존 프로젝트를 쓰면 앱의 공개 URL·키 설정을 그대로 사용할 수 있습니다. 다른 프로젝트를 쓰면 `shared/config.mjs`의 공개 URL·publishable key만 바꾸고 `python3 scripts/prepare_unified.py` 후 다시 빌드합니다. service-role key를 앱에 넣지 마세요.
5. 다른 NAT 환경의 연결이 실패하면 설정에 본인 TURN 서버를 추가합니다. TURN 중계 트래픽은 별도 비용이 들 수 있습니다.

앱은 ID를 로그인 비밀로 사용하지 않습니다. Supabase 인증 UID와 기기의 보호 저장소에 보관하는 세션을 사용합니다. 익명 계정에서 이메일 복구를 연결하기 전에 앱을 삭제하면 계정을 잃을 수 있습니다. 프로필의 복구 설정을 먼저 확인하세요.

## 설치와 사용

- Windows: `Solaris-Windows-build55-Setup.exe`. 단일 설치판에 FFmpeg가 포함되고 WebView2 설치를 확인합니다. Python은 필요 없습니다.
- Android: `Solaris-Android-build55-debug.apk`. 디버그 서명의 테스트판입니다. 화면공유를 시작할 때 시스템 화면 캡처 승인 창이 표시됩니다.
- iOS/iPadOS: `Solaris-0.4.0-build55-resign.ipa`. AltStore 등으로 재서명해야 합니다. 앱과 방송 확장의 같은 Solaris App Group을 실제 프로비저닝 프로필이 허용해야 합니다. 공유 권한이 유지되지 않으면 인증된 화면공유가 오류로 종료됩니다. 해당 환경의 설치·서명 성공은 별도 검증 항목입니다.

처음 ID와 닉네임을 생성하고 친구의 고유 ID로 요청합니다. 상대방이 수락하면 화면공유 요청과 파일 보내기를 사용할 수 있습니다. 화면공유 요청도 수락해야 개인 연결이 열립니다. 서버는 초대코드로 참여하고 채널의 방송 목록에서 시청을 선택합니다. 영상은 선택한 시청자에게만 전송합니다. 마이크 및 음성통화는 없습니다.

파일은 수신자가 저장을 승인한 뒤 원본 그대로 직접 전송합니다. 부분 파일과 SHA-256 상태는 기기에 보관합니다. 전송을 일시정지한 뒤 이어받기로 재개할 수 있습니다. 모바일에서는 앱을 화면에 유지하세요. OS가 앱을 중단한 동안의 전송은 보장하지 않습니다. 파일은 자동 실행하지 않습니다.

## 빌드와 검증

`npm ci`, `npm test`, `npm run test:database`, `npm run test:browser`로 공통 엔진과 권한 검증을 실행합니다. `node scripts/unified_browser_test.mjs --large`는 별도의 1GiB 전송 검증입니다. 자동 테스트의 영상 소스는 합성 캔버스이며 실제 캡처 성능을 증명하지 않습니다. 플랫폼 빌드는 GitHub Actions에서 수행합니다.

정식 릴리스는 저장소 소유자가 검증 후 승인합니다. 개발 브랜치의 Actions 빌드가 정식 업데이트로 자동 게시되지 않습니다. 테스트 결과 및 남은 항목은 `docs/BUILD55_STATUS_KO.md`에서 확인합니다.
