# Solaris 0.4.0 build64 · UI 정리

build64은 Solaris에 이미 있는 기능을 Discord의 현재 데스크톱·모바일 UI 구조에 맞춰 정리한다.

## 참고 기준

- [공식 데스크톱 개편 이미지](https://discord.com/blog/player-release-q12025): 서버 목록, 채널 목록, 메시지, 입력창, 하단 사용자 패널.
- [공식 설정 창 개편 이미지](https://discord.com/blog/a-cornucopia-of-updates-make-discord-on-desktop-fresher-than-a-crisp-fall-breeze): 떠 있는 설정 창과 왼쪽 설정 목록.
- [공식 모바일 개편](https://discord.com/blog/improving-mobile-with-squircles-styles-and-spacing): 사람은 원형, 서버는 둥근 사각형, 작성창의 여유 공간.
- [공개 Discord 로그인 페이지](https://discord.com/login)의 공통 CSS 값(2026-10-13, `theme-darker`/`density-default`): 바탕 `#121214`, 목록 `#1a1a1e`, 대화 `#202024`, 높은 표면 `#242429`, 기본 강조 `#5865f2`; 반경 4/8/12/16px, 간격 8/12/16/20px. 공개 스타일의 제목 표시줄 32px, 메시지 아바타 40px, 입력창 높이 56px도 참고했다.

공개 이미지는 비교 자료로만 사용한다. Discord 로고·캐릭터·앱 코드·전용 글꼴을 배포하지 않는다. [gg sans는 다른 프로젝트용으로 공개되지 않았다](https://support.discord.com/hc/en-us/articles/9507780972951-gg-sans-Font-Update-FAQ). Solaris는 시스템 글꼴과 자체 SVG 아이콘을 사용하므로 픽셀 단위로 완전히 동일한 복제는 아니다.

## 변경점

- 친구 행의 큰 메시지 버튼을 원형 메시지·더보기 아이콘으로 정리하고, 이름을 눌러 대화를 연다.
- 친구 화면의 중복 온라인 친구 패널을 기본 화면에서 접는다. 참여자 버튼과 실제 공유 요청 배너로 요청 패널을 열 수 있다.
- 서버 아이콘은 둥근 사각형, 사람 아바타는 원형으로 통일한다. 목록 선택·마우스 호버·포커스 상태를 구분한다.
- 내 프로필과 설정은 하단 사용자 패널에 모으고, 중복 계정·로그아웃 버튼을 제거한다. 로그아웃은 설정 목록에 있다.
- 대화 헤더의 화면공유·중지·더보기·참여자 조작을 일정한 크기의 아이콘으로 정리한다. 이름과 툴팁을 유지한다.
- 데스크톱 더보기 메뉴를 누른 버튼 근처에 열고 화면 밖으로 벗어나지 않게 조정한다. Escape와 닫기 버튼으로 닫으면 원래 버튼에 포커스가 돌아간다.
- 설정 창은 왼쪽 카테고리·오른쪽 내용으로 정리한다. 모바일에서는 가로로 넘기는 카테고리와 세로 내용으로 표시한다.
- 모바일 주요 버튼은 최소 44px 터치 영역을 확보하고, 입력창·하단 메뉴·설정 창 스크롤을 점검한다.

친구/DM, 서버/채널, 화면공유, 원본 파일 전송, 프로필, 계정, 설정, 로그아웃만 재배치했다. Nitro·음성 통화·앱 스토어 등 새 Discord 기능은 추가하지 않았다. build63 Google 인증 복귀·기존 UID 보호, build54 화면공유 엔진 및 품질 정책은 유지한다. 새 Supabase SQL이나 인증 설정 변경은 필요 없다.

## 설치와 확인

Windows 설치 파일 또는 portable ZIP, Android debug APK, iPad 재서명용 IPA의 버전은 모두 build64다. iPad IPA는 사용 중인 서명 도구로 앱 그룹을 포함해 재서명해야 한다. Android debug APK는 CI 실행마다 서명자가 달라질 수 있으므로 설치된 APK와 서명이 다르면 바로 업데이트되지 않는다. 기존 계정의 복구 수단을 확보하기 전에는 앱 데이터를 삭제하지 않는다.

자동 브라우저 검증은 실제 화면 크기 1280·1024·860·390px에서 버튼 충돌, 메뉴 동작, 포커스 복귀, 요청 동의, 설정 스크롤 및 기존 인증·로그아웃을 확인한다. 실제 기기의 Google 제공자 로그인이나 GPU/MediaProjection 송출 품질은 실기기 확인이 별도로 필요하다.
