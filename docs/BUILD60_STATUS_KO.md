# Solaris build60 구현 및 검증 결과

빌드60은 저장됐던 빌드59 중간 소스에서 이어서 개발했다. 최신 지시에 따라 1GB 이상 대용량 파일 전송을 범위에서 제외하고, 일반 파일 전송을 최대 100MiB로 제한했다. 검은 화면·전체화면 잔류·입력 차단의 공통 정리 경로를 수정했고, 개인 메시지와 화면공유 세션을 분리했다.

## 구현 변경

- 실패·시청 종료 때 로컬 영상/피어/마스크/전체화면을 서버 응답보다 먼저 정리한다. 네이티브 시작 실패, 시작 중 종료, 오래된 connectionID도 처리한다.
- 자동 시청 복구는 2회 실패 뒤 명시적인 `다시 시청`으로 전환한다. 재연결 중에는 안내를 표시하며 정상 연결의 정지 화면을 장애로 처리하지 않는다.
- 수신 슬롯 요청과 정리를 계정별로 직렬화한다. 동시 요청이 시청 수 제한을 우회하지 못하며, 겹친 진단 tick을 막는다.
- Android custom video fullscreen에서 WebView·시스템 바·insets를 복원한다. 허가 취소/캡처 실패/렌더러 종료 경로와 재진입 callback을 정리한다.
- iOS 수신기를 종료하면 그 수신기를 보유한 전체화면을 닫는다. 네이티브 영상은 스크롤 영역에 마스크를 적용하며 메뉴와 대화상자 위로 남지 않게 숨긴다. ReplayKit 시작 취소는 선택 시트도 닫는다.
- 친구 DM을 영구 저장하고, 화면공유 연결 없이 텍스트를 보낼 수 있다. 오프라인 텍스트 수신, 날짜·시간·프로필·묶음 메시지, 전송 실패 재시도, 읽지 않은 개수, 여러 줄 입력, 이전 대화와 최근 대화 이동을 구현했다.
- client_id 멱등 처리, UID별 저장과 오래된 응답 격리, 200개 로컬 캐시/이전 표시 창, 메시지 DOM 유지와 저장 묶음 처리를 적용했다. 인증·테스트 안내를 개인 대화 목록에 섞지 않는다.
- 앱·서버·Windows/Android/iOS 수신 파일 브리지에서 100MiB 제한을 검증한다. 큰 파일은 해시 계산 전에 거절하고 예전 큰 전송의 자동 재개를 막는다. 1GB 전용 CI 작업과 스트림 시험을 제거했다.

## 미검증 및 제한

- Windows·Android·iOS·iPadOS의 실제 기기 캡처/충돌/터치 복구/전체화면/네트워크 전환: 미검증.
- 실제 기기의 1080p60·1440p60·지연·CPU·발열, 5인 수신 품질: 미검증. 원본 코드 해시 일치는 실제 성능을 보장하지 않는다.
- 이 실행 환경에서는 네트워크 인터페이스 조회가 차단돼 실제 WebRTC ICE/P2P 연결 시험이 **차단됨**으로 기록됐다. 이를 통과 결과에 포함하지 않았다.
- iOS/Swift 컴파일·IPA 생성·AltStore 서명 및 App Group 설치: 미검증. 새 GitHub Actions/Xcode 결과가 필요하다.
- Windows 설치 EXE: 이 세션에서 생성하지 않았다. 새 GitHub Actions 결과가 필요하다.
- 실제 Supabase 배포: 수행하지 않았다. 기존 프로젝트 소유자가 `backend/003_build60_dm.sql`을 적용해야 한다. DB와 계정 테스트는 격리된 로컬 SQL/인증 환경에서 수행했다.
- 일반 파일은 온라인 상대에게 최대 100MiB이다. 앱을 재설치하거나 다른 기기로 바뀐 부분 파일의 복구를 보장하지 않는다. 오프라인 파일 보관/서버 업로드는 제공하지 않는다.

## 적용 및 다음 작업

`START_BUILD60_KO.md`대로 DB 업데이트와 소스 업로드를 진행한다. 모든 테스트 기기를 build60으로 맞춘 뒤 Windows↔Android와 Windows↔iPad부터 1080p60 및 실패 시 복구를 확인한다. 결과가 없는 항목은 완료로 기록하지 않는다.
